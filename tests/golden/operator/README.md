## `emax2/` (emax 2, hw 16, 2N only)

| file | content |
|---|---|
| `H_NO_O16.dump` | `hamiltonian/emax2_O16/H.dump` normal ordered w.r.t. O16 (`normal-order ... reference=O16`) |
| `H_NO_O16_undo.dump` | `UndoNormalOrdering` of `H_NO_O16.dump` (`undo=true`); reproduces `H.dump` |
| `randomH_NO_Ne20.dump` | `commutator/emax2_O16/random_H.dump` normal ordered w.r.t. Ne20 (fractional occupation 1/3 in 0d5/2) |
| `randomA_NO_Ne20.dump` | `commutator/emax2_O16/random_A.dump` (anti-Hermitian) w.r.t. Ne20 |
| `C_HF_O16_2N.txt` | field `C` of `hf/emax2_O16_2N/hf.json`, `%.17g`, row = HO orbit, column = HF orbital |
| `H_HFbasis.dump` | `TransformToHFBasis(H.dump)` with that C |
| `norms.json` | `refharness norms` of every dump, keyed by file stem |

Every dump roundtrips byte-identically (`tools/reference/check_roundtrip.sh`: 37 dumps pass) and
is below 100 KB.

## Notes on old-code behaviour

* The antisymmetric `random_A` has zero_body 0 after normal ordering (an anti-Hermitian operator
  has no scalar part).
* `read_opdump` requires the dump's occupations to equal the model space, so `normal-order`
  copies the data into a model space built for the target reference.
* `.venv/bin/python` was not available; the script uses `python3 -I` with the standard library.
