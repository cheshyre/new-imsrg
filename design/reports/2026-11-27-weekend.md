## Summary

All three variants of the owner's 2024 VS-IMSRG(2) 27Al NREFT response set were produced with the
rewrite on Frontier, for both Hamiltonians (N2LOsat, ΔN2LOGO(394)), 34 operators × 71 q + TCM each.

* **v1 (fork compat) reproduces the archive:** every archived `.snt` element to ≤ 1e-9 with native
  float64 Omegas (the archive's last printed digit) and ≤ 1e-6 with ME2JP float32 Omegas, against the
  1e-4 target; the flows already matched README §3.3. Archive gaps (six ΔN2LOGO FM2p values at
  q = 975-1050 MeV, FPhitp2/4) are filled.
* **v2 (default solver, unsplit) and v3 (split Magnus, omega_norm_max 0.25)** converged for both
  Hamiltonians; difference reports in `design/benchmarks/al27-variants.md`. v2 differs from v1 by
  ~4 keV in E0; its tensor operators differ by up to 0.10, almost all from the fork bugs that v1
  emulates (measured one compat option at a time, Lead E: M15-1 at every rank L >= 1, AL-F1 in
  addition for odd L; al27-variants.md 4.3). **v3 differs from v2 by -0.47 /
  +0.08 MeV in E0 and by a median 4-9 % in the dominant operator elements; this is the truncation
  error of the unsplit Magnus(2) flow:** ODE IMSRG(2) flows from the same H_0 agree with v3 to
  15.5 / 2.2 keV (and with v3's scalar operators to 0.1-0.3 % / 0.08-0.4 %), but differ from v2 by 487 / 81 keV.
* **GPUs:** flows (one per GCD, 40-47 min) and farm items (3-125 s, TCM 750 s host-bound) run on
  the GCDs; GPU = CPU to ≤ 6e-16 on test items and 6e-18 on the whole v1 native farm.
* **Cost: ~270 node-hours of production and validation jobs** (estimate 1,500-3,300; budget 50,000),
  because the GPU farms were sized for efficiency (30-80 nodes) instead of 600-1,200 nodes (D77:
  "use the GPU resources efficiently").
* **Lost time:** a usage-limit stop at Fri 02:15 stalled all agents and the orchestrator for ~16 h
  (the one-shot upkeep chain broke; now a recurring scheduled task).

## Fork/devel bugs found

* Known before the weekend and emulated in v1: M15-1 (tensor normal ordering, a == b term) and AL-F1
  (odd-rank ph phase) of the fork; measured per option (Lead E, al27-variants.md 4.3) they are the
  whole operator side of the v2-v1 tensor differences, M15-1 the larger part at every rank L >= 1
  (one-body elements only), AL-F1 an addition for odd L.
* imsrg++'s integer tensor one-body degeneracy (AL-A-Q6) is already negative at emax 4, not first
  at emax 10 (lead B); the default now uses (2j_p+1)(2j_q+1)/(2L+1).
* WE-D-1: the devel tokyo writer drops TCM two-body elements below ~1e-3 (relative threshold 1e-7 ×
  norm2b) in the v2/v3 TCM files; the fork writer (v1) writes all 158.
* Bugs of the rewrite found this weekend, all fixed: lock-based lazy host mirror deadlocking through
  the global Kokkos fence on HIP (review of lead A); `farm_sweep.sh` heredoc joining the srun lines;
  `flows_chain.sh` passing an empty argument and not overriding `output.flow_file` (overwrote the
  production v3 N2LOsat `flow.txt`, restored from the bit-identical straight re-run, sha256
  1feac99b...; the v3 tarball was rebuilt); stale farm-plan test weights; config hash covering the
  whole schema (WE-A-4); a restarted link rewrites `flow.txt` from the restart step (WE-R-1, fixed on feature/al27-investigate-variants).

## Deviations from the plan

* Lead C was started at once (not after Phase 0) and did the Phase-0 J = 0/1 and TCM checks on CPU,
  then the whole native v1 farm on CPU as insurance (161 nh) before the GPU path was merged; ME2JP
  and a native rerun then ran on GPUs.
* Farm jobs were sized at 30-80 nodes (TCM-bound ~13-45 min), not 600-1,200 nodes: a 1,200-node job
  would idle most GCDs (lead A, WE-A-2; owner D77: efficiency over rank count).
* Brief E was not needed: no v1 column missed 1e-4.
* Extra: the v3-vs-v2 investigation used a domega/threshold scan and ODE IMSRG(2) reference flows.
* A ~16 h stall (usage limit) and the orchestrator's clone clean-up, which made lead D unresumable
  (its review fixes went to a fresh implementer).

## Path to 19,320 ranks

19,320 ranks = 8 farms (v1 native + ME2JP, v2, v3; 2 Hamiltonians each) × 2,415 items, one item per
GCD: one 2,415-node job of ~13 min (~520 node-hours), bounded by the TCM item (750 s, host-bound
preparation at basis emax 14). TCM is already written by every flow (WE-A-3), so dropping it from
the farm work list brings the job to ~2-4 min (~90-160 node-hours) at 2,415 nodes. Nothing in the
farm prevents it (Omegas in node-shared memory, static LPT assignment, failure manifests); it was
not run because 30-80-node jobs did the same work at 10-60 % of the cost.
